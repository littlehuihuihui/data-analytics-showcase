>_ 分析框架速览

① 问题拆解框架

业务问题 → 口径定义 → 数据诊断 → 根因定位 → 方案推动 → 效果验证 → 机制固化

② 常用分析模型

  • 漏斗分析：用户生命周期（开户→激活→活跃）+ 行为（开机→点播→播放）+ 订购（浏览→下单→支付→开通）
  • 分层分析：用户价值金字塔 + R×F×M + 告警分级
  • 同期群分析：按批次对比；首批用户到期流失高峰约第13个月
  • 对比分析：对照组评估策略（一键登录优化前后）
  • 行为占比分析：播放次数/时长占比构建内容偏好
  • 流失预估：优惠到期、仅开机一次、沉默月份数三类特征分层

③ 口径定义原则

从业务定义出发 → 找到数据源 → 验证质量 → 统一标准 → 固化为看板指标。入职初期梳理数据字典与埋点文档，明确核心字段定义、来源与关联。

⑤ 数据资产沉淀

爱立信：原始告警表上建 issue-record-tracking；5字段组合唯一键；每日增量比对四状态（新增/持续/待观察/已解决），告警全生命周期闭环。状态机与 OTT 用户状态表（新增激活/持续活跃/沉默/流失）底层方法论一致。

银河OTT：8 个 Datart 看板替代人工取数、数据字典可查口径、三方关联框架复用；陪产假前客服查询上线 BI，团队免 SQL 自助，休假业务未受影响。

⑥ 协作模式

与运营分工：数据挖掘与异常定位（数据侧）+ 策略与报告（运营侧），共同完成用户质量、活跃度等报告。

220万虚假用户 · 口径对齐与真实活跃率

场景还原：刚入职时，移动质疑运营能力——400万用户、活跃仅约40万；银河后台激活设备约180万。两队口径不一，无人能说清差异。

> 思维路径

  1. 抛出问题：400万 vs 180万，活跃率无法确定
  2. 还原口径：移动营业厅登记（手机号，意向）vs 银河设备首次 PB 日志（MAC，行为）
  3. 数据定位：按口径找表；两套标识需设备绑定验证映射
  4. 推动共识：用数据证明流程差异非单方错误；统一为「激活设备」
  5. 落地：合规下不能批量销户，优惠到期逐步处理，对外解释为正常流失

> 口径对比

来源规模判定标识本质

用户全生命周期分析框架

开户→激活→活跃（R×F 四象限）→沉默→离网。四象限：高价值（R近F高）、休眠老用户（R远F高）、新用户/低活跃（R近F低）、流失（R远F低）。特殊：仅开机一次、深度沉默（≥3月）。覆盖开户质量、活跃分层、沉默诊断、离网预警、唤醒效果跟踪。

告警生命周期管理系统（issue-record-tracking）

原始告警无法回答「是否已解决」。在原始表之上建跟踪表；唯一键：省市名+网元类型+网元名称+告警名称+告警描述关键词（正则）。每日增量比对：持续 / 新增 / 待观察 / 已解决。

与 OTT 用户状态对应：新增→首次激活；持续→持续活跃；待观察→沉默；已解决→流失/销户。
